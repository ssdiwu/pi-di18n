# 路线图

`pi-di18n` 的演进路线。本文记录已对齐的方向和阶段，具体决策依据见引用的 ADR / 术语表。

## 背景

pi-di18n 当前已落地两条 i18n 战线：

- **A 线 — TUI 本地化**（给人看）：`core-hacks` 运行时 patch pi 内部渲染路径，覆盖按钮、状态、selector、slash 命令描述。已有 zh-CN/zh-TW 修复、25 locale bundle、`/lang debug` + `/lang probe` 诊断。
- **C 线 — 摘要本地化**（给人看）：整合自 `pi-compaction-i18n`，接管 `session_before_compact` / `session_before_tree`，让压缩与分支摘要跟随 `/lang` locale。

本路线图聚焦新开的 **B 线 — 思考语言本地化**（给 LLM 看）：让 pi 发给 LLM 的 prompt 自适应用户 locale，使 LLM 倾向用目标语言思考和回复。

## B 线总览

```
用户 /lang zh-CN  →  TUI locale = zh-CN（A 线现有）
用户 /lang think on →  开启思考语言本地化（B 线新增）

触发流:
  session_start          → 预翻译（异步）：扫 tools+skills，缺的用 session 模型翻，写缓存
  before_provider_request → 兜底+替换：
     每条 description 查三层 → 替换为目标语言 → LLM 读到目标语言工具说明

三层翻译源:
  ① 预制 baseline（随包，12 语言已翻好）
  ② 翻译缓存（~/.pi/agent/state/pi-di18n/think.json，用户本地，带英文原文比对）
  ③ 都 miss → 同步 LLM 翻译兜底
```

详细术语见 [术语表.md](../术语表.md)，关键决策见 ADR（`决策档案/`）：

- [ADR 0001](../决策档案/0001-llm-thinking-language-localization.md) — 运行时翻译路线（含不翻 system prompt、不做多模型）
- [ADR 0002](../决策档案/0002-only-translate-description-not-fields.md) — 只翻 description，不碰字段名/type/enum/值；默认关
- [ADR 0003](../决策档案/0003-prefilled-baseline-12-languages.md) — 预制 baseline 覆盖 12 种语言

## 12 项决策摘要

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 范围 | tool / param / skill description；pi 核心 system prompt 本体暂不翻 |
| 2 | 翻译路线 | 运行时 LLM 翻译 + 落盘缓存 |
| 3 | 翻译源 | locale 驱动三层：预制 → 缓存 → LLM |
| 4 | 翻译模型 | session 当前模型，不配置 |
| 5 | LLM 调用 | 独立调用（不借对话回合） |
| 6 | 翻译时机 | `session_start` 预翻译 + `before_provider_request` 兜底，异步 |
| 7 | 开关 | 默认关 |
| 8 | 字段边界 | 只翻 description 散文，不碰字段名/type/enum/值 |
| 9 | 预制策略 | 随包预制 baseline + 新工具走运行时兜底 |
| 10 | 预制语言 | 12 语言（zh-CN/zh-TW/ja/ko/ru/vi/es/pt-BR/de/fr/id/hi） |
| 11 | 缓存失效 | 存英文原文比对，原文变即重翻 |
| 12 | 命令设计 | `/lang` 定语言，`/lang think` 不持有 locale；on/off 控制开关，doctor/clear 做诊断与缓存维护 |

## 实施阶段（垂直切片）

每个切片独立可验证，从最小到完整。

### 切片 0 — 数据准备：预制 baseline 生成

**目标**：生成 12 语言的 tool/param/skill description 预制表。

- 导出 pi 自带工具的英文 description（约 7 工具）+ 参数 description
- 为 12 语言各生成翻译（离线 LLM 翻译，随包发布）
- 落到新的预制表文件（独立于 `src/core-hacks-locales/`，因消费者不同）
- **验证**：文件结构校验、12 语言齐全、description 数 = pi 自带工具数 × (1 + 参数数)

### 切片 1 — 核心通路：think on/off + session_start 预翻译 + before_provider_request 替换 ✅

**目标**：最小可用的思考语言本地化闭环。

- `/lang think` 子命令解析（on / off / doctor / clear / clear-all / 无参查状态），写配置到 `~/.pi/agent/state/pi-di18n/think.json`
- `session_start` hook：`pi.getAllTools()` + 扫 skills → 比对缓存 → 异步预翻译（用 session 模型，复用 `pi-compaction-i18n` 的 `runSummary` + `resolveModelAuth` 模式）
- `before_provider_request` hook：三层查询替换 `payload.tools[].function.description`；缓存 miss 时同步兜底翻译
- 缓存读写：`~/.pi/agent/state/pi-di18n/think.json`，结构 `{enabled, locales: {locale: {tool: {...}, param: {...}}}}`，每条带英文原文做失效比对
- **验证**：`/lang think on` → 发消息 → 用抓包/日志确认 LLM 收到的 description 是目标语言；`off` 后恢复英文

### 切片 2 — 预制 baseline 接入 ✅

**目标**：12 语言开箱即用，跳过首次翻译等待。

- 切片 0 的预制表接入三层查询的第①层
- 预制命中即跳过 LLM 调用
- **验证**：12 语言 baseline 均为 `tool=7` / `param=21`，`getBaselineTranslation(locale, "tool", "read")` 对 12 语言全命中且非英文原文；zh-CN 真实 `pi -ne -e` 进程中 LLM 复述 baseline 中文（"读取文件内容"、"图片以附件发送"、"2000 行或 50KB 截断"）

### 切片 3 — 健壮性与可观测性 ✅

**目标**：处理边界情况，加诊断。

- 翻译竞态：后台预翻译 vs 兜底同步翻译写同一 key 的并发安全（in-flight Promise map 去重；同步兜底等待已有翻译，后写覆盖）
- 翻译失败降级：该条回退英文，不阻塞（`translateBatch` 失败返回空 Map）
- `/lang think doctor`：报告 baseline 覆盖、缓存条数、过期（英文原文变了）、pending 条数
- `/lang think clear` 清当前 locale 缓存，`/lang think clear-all` 清全部 locale 缓存
- **验证**：vitest 覆盖 OpenAI/Anthropic/Google provider payload 的 tool/param description 替换、doctor 诊断、过期检测、pending 计数、clear/clear-all；真实 `pi -ne -e` 下 `/lang think clear` 通过副作用清空 `think.json` 的 locale 缓存

### 切片 4 — 测试与文档

- vitest 覆盖：命令解析、三层查询、缓存失效比对、竞态
- 更新 `index.ts` 入口说明、`doc/` 验证记录
- README 加 B 线使用说明

## 风险与边界

| 风险 | 触发 | 应对 |
|---|---|---|
| 翻译竞态 | 后台预翻译与兜底同步翻译同写一 key | 写入用"后写覆盖"+ 内存去重 |
| LLM 翻译失败 | session 模型调用失败 | 该条回退英文，不阻塞主对话 |
| pi 升级 description 变 | 缓存英文原文与现版不一致 | 存英文原文比对，不一致即重翻 |
| 第三方扩展含 enum | 用户装的扩展 schema 有严格校验 | ADR 0002 约束不碰 enum，安全 |
| 兜底阻塞首条消息 | 后台没翻完且用户立刻发消息 | 只同步翻缺失项，已有项零成本；超时降级英文 |

## 挂账（B 线之外，待办）
