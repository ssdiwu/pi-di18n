## pi-tui 在渲染时才换行，长句词典条目永远匹配不上

**现象**：为编辑器说明、设置描述等长句配的 exact 词条不生效。上游组件 render 时才把长字符串按屏宽折行，词典里按完整句子组织的 key 在折行后的每一行上都匹配不到。

**做法**：不要在行级兜底里解决这个问题——在组件 render 前翻译**源文本**（`localizeSourceTextNodes`：递归 Text 子节点，折行前替换），让正常折行发生在译文上。行级 `tUiLine` 只负责短行和已拼接行。

**证据**：`src/core-hacks.ts` `localizeSourceTextNodes` + `patchRenderableComponent`；CHANGELOG 0.2.2「Fixed long sentences … never matching a dictionary entry」。

## 会话运行时状态随缓存落盘，会毒化磁盘全局默认

**现象**：think 的全局默认被写成 `enabled: false` 后，每个新会话都启动为关闭；会话级 `/lang think on` 修不回来（按设计不落盘）。根源是旧版 on/off 直接落盘 + 缓存写入把整个 cache 对象（含会话运行时的 `enabled`）序列化回磁盘。

**做法**：磁盘字段和会话内存字段语义分离——落盘时把"磁盘全局默认"单独保存（`diskEnabled`），任何缓存写入都写全局默认而不是会话运行时值。判断标准：这个字段的合法写入者是谁？如果只有用户/配置该改，运行时就必须绕过它序列化。

**证据**：`src/think/cache.ts` `diskEnabled` + `saveCache`；`tests/think-pipeline.test.ts` 两条毒化回归；`verification-2026-11-14.md` 真实 TUI 复现记录。

## 行级宽度保护会截断比原文宽的枚举值译文

**现象**：设置值 `all` 显示为「全…」——`tUiLine` 的"译文不超原文宽度"保护把宽译文截断。该保护本意是防译文撑爆已被上游定宽的行，但设置值不是预宽行，上游 `renderMainList` 自己会按剩余宽度截断。

**做法**：宽度保护只该用于"上游已按原文宽度定版"的场景（提示行、拼好的行）。独立渲染字段的翻译走无宽度限制的管道（`tSelector ∘ tCore`），截断交还给上游。新增翻译管道前先问：这个文本渲染时上游会不会重新排版？

**证据**：`src/core-hacks.ts` patchedRenderMainList 注释；`tests/settings-localization.test.ts` 宽度回归（`all → 全部` 不含 `…`）。

## `/tree` 导航不发 `session_start`（引用 dgoal 同款坑）

**现象**：只监听 `session_start` 的状态同步在用户 `/tree` 切分支后失效。

**做法**：同时监听 `session_tree`。pi 的 `navigateTree` 是原地切分支，只发 `session_before_tree` + `session_tree`，不重建 runtime。本项目 compaction 已接管 `session_before_tree`；后续新增"跟 session 走的状态"都要核对这条。

**证据**：pi 主程序 `agent-session.js` `navigateTree`（详见 `pi-dgoal/doc/经验笔记.md` 同名条目）。
