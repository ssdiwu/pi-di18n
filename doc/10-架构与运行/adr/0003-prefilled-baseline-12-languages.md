# 思考语言本地化预制 baseline 覆盖 12 种语言

## 背景

思考语言本地化的 tool/param/skill description 预制翻译表（方案 B）第一版覆盖哪些语言，直接影响开箱即用范围和包体积。

## 决定

预制 baseline 覆盖 12 种语言：zh-CN、zh-TW、ja、ko、ru、vi、es、pt-BR、de、fr、id、hi。其余 13 种 locale 走运行时 LLM 翻译兜底（方案 A），能力不丢，只是首次翻译等几秒。

## 为什么

语言优先级综合三个证据信号排序：

1. **GitHub 多语言内容体量**（arXiv 论文）：非英文内容前 5 大语言是 Chinese、Korean、Japanese、Russian、Vietnamese——这是"真实开发者用母语编程体量"的硬数据，直接对应"LLM 母语思考痛感"。
2. **与英文的语言距离**：东亚语言（中/日/韩）和俄语、越南语与英文差异最大，英文思考认知负担最重。
3. **母语者基数 + 现有投入**：西班牙语、葡语（拉美）、德语、法语、印地语、印尼语覆盖主要人口和开发者大国。

12 种分两档：
- 前 8（zh-CN/zh-TW/ja/ko/ru/vi/es/pt-BR）：强证据，GitHub 数据 + 语言距离双重支撑。
- 后 4（de/fr/id/hi）：市场体量支撑，但痛感证据偏弱（de/fr 与英文亲缘近；hi/id 开发者社区高度英文化，真实利用率可能低）。纳入是为了覆盖主要人口大国、对外支持语言数更完整。

## 为什么不全覆盖 25 语言

体积杠杆：7 工具 × 25 语言 + param ≈ +70-200 KB，相对现包 85.8 KB（gzip）接近翻倍。为 cs/da/fi/el 等欧洲低频语言背体积不划算——它们英文痛感低，运行时兜底完全可接受。

## 维护循环

pi 升级新增工具时：新工具的 description 自动走运行时兜底（A），验证稳定后在后续版本固化进预制表（B）。12 语言列表本身按真实下载/反馈数据演进，不锁死。
